# Контракт восстановления 0.3.0-dev

Статус: опубликованный код разработки, без отдельного выпуска. На клиентские устройства этот код не устанавливался. Ранее проверенная/опубликованная 0.2.1 не получает исправление от появления этой папки.

## Адаптеры

Адаптеры объявлены отдельными функциями в `recovery.sh`, общий код выполняет блокировку, контроль конфигурации и бюджета. Результат метода — код возврата и типизированные `REASON`/`PROBE_CODE`; исходный вывод native-команд остаётся приватным. Контракт `adapter METHOD`: `detect`, `read_section`, `get_current_interface`, `set_interface`, `apply`, `runtime_state`, `ensure_started`, `verify_binding`, `verify_path`, `rollback`.

| Адаптер | Поле интерфейса | Родное применение | Идентичность маршрутизации |
| --- | --- | --- | --- |
| Podkop | `podkop.<section>.interface` | `/etc/init.d/podkop reload` при работающем движке, иначе `start` | `PodkopTable`, таблица `podkop`, outbound `<section>-out` |
| Forkop | Единственный дочерний `section_interface`, принадлежащий секции: `<child>.name`; поддержанные одиночные legacy-поля `section_interface`/`interfaces`/`interface` | `/etc/init.d/forkop reload` либо `start` | `ForkopTable`, таблица `forkop`; outbound по `label` секции, иначе UCI-имени; одиночный selector до direct leaf |
| Forkozz/NetShift | `netshift.<section>.interface` | `/usr/bin/netshift reload` либо `/etc/init.d/netshift start` | `NetShiftTable`, таблица `netshift`, outbound `<section>-out` |

Forkop 2 изучен по исходникам `ushan0v/forkop` @ `400daf1e1be9cc546ae662c091984cffae874423`. NetShift — по локальному срезу `3d5c24f28799502db16e76b6475ce38c7f0def33`. Это проверка схем исходного кода, а не подтверждение всех версий на устройствах. Смешанные proxy/subscription/tunnel-группы, несколько интерфейсов/ветвей selector и неизвестные схемы отклоняются. Секции proxy/direct не переводятся в VPN.

Нативный lifecycle должен сначала сгенерировать конфигурацию, затем применять её/запускать движок. После его завершения проверяются поле bind и `sing-box check`; остановленный sing-box допускается запустить только при совпадении `sing-box.main.conffile` и установленном `main.enabled=1`. Утилита **не меняет** этот флаг и не вызывает enable/disable backend/движка. Контракт стандартного init сверён с [OpenWrt packages sing-box.init](https://github.com/openwrt/packages/blob/master/net/sing-box/files/sing-box.init).

## Диагностика туннеля без sing-box

Выбор серверов не зависит от имени awg*: используется явный список секции, netifd, peer endpoint, маршрут до endpoint, рукопожатие и увеличение входящих байтов. Разрешённый резерв можно поднять адресным `ifup`; текущий рабочий интерфейс не опускается. Несколько peer либо неизвестный endpoint дают неопределённый результат вместо ложного отказа.

Тестовые HTTPS-ресурсы: Cloudflare `/cdn-cgi/trace` и Microsoft `/connecttest.txt`. Проверяются сертификат, код 200 и формат/точное содержимое ответа. Оба ресурса проверяются; одного корректного ответа с данными и handshake достаточно, чтобы отдельный отказ провайдера теста не объявлял VPN упавшим. При заданном ожидаемом egress требуется также результат Cloudflare с совпадающим IP; учитывай фактический Exit node.

IP адреса ресурсов получают через pinned HTTPS DoH Cloudflare/Google, с сохранением имени и проверки сертификата. Локальный DNS/FakeIP и смешанный прокси не нужны. Ответы private/FakeIP не принимаются. Кеш адресов живёт до 300 секунд по uptime в `/tmp`. Если основной туннель не может получить DNS, разрешённые резервы проверяются независимо и могут заполнить кеш; основной повторно тестируется с известными адресами. Ошибка инфраструктуры сама по себе не повышает счётчик отказа AWG.

Для сокетов с `--interface` используется отдельное временное правило `oif`, ранее пустая таблица 42800–42807 и свободный приоритет 1–8 до других policy rules; собственные записи помечаются protocol 186. При конфликте проверка отклоняется. Удаляются только точные собственные записи по манифесту, не выполняется flush. IPv4-проба допускает IPv6 endpoint, но не является проверкой клиентского IPv6-маршрута.

## Доказательство восстановления обхода

Одних UCI, bind и прямого AWG-теста недостаточно. Проверяется один живой procd PID sing-box с правильными argv/config, синтаксис конфигурации, отсутствие смены PID и новых fatal/crash за 10 секунд, direct leaf нужной секции, nft-таблица backend и его policy rule/local route.

Затем проверяется HTTPS **внутри уже работающего движка**. Используется существующий loopback mixed inbound без авторизации, только если первая безусловная route rule эксклюзивно направляет его в выбранную секцию; либо существующий Clash API, доступный через localhost, с URL-test именно outbound выбранной секции. Wildcard bind существующего API доступен через 127.0.0.1; новые listeners/порты не создаются. Отрицательный URL с `.invalid` должен провалиться, два независимых положительных URL проверяются отдельно.

Если движок не предоставляет такой путь, возвращается `PATH_TEST_UNAVAILABLE`. Код не подменяет его прямым AWG-запросом и не называет восстановление успешным. При провале после переключения возвращается только собственное поле, если конфигурация не менялась извне. Проверка прежнего маршрута обязательна; сам возврат поля не делает состояние успешным. На версиях без подходящего API/inbound готовность требует отдельной доработки адаптера после изучения версии; публичный тестовый прокси автоматически не включается.

## Ограничения и совместная работа

Состояния: `PAUSED`, `OBSERVING`, `PROBING`, `APPLYING`, `STARTING_BACKEND`, `VERIFYING`, `RECOVERED`, `ROLLING_BACK`, `WAITING_NETWORK`, `NO_HEALTHY_RESERVE`, `RECOVERY_FAILED`.

По умолчанию: 3 отказа, 2 положительные проверки кандидата; одна операция до 180 секунд, из них 2 секунды зарезервированы на очистку; ожидание runtime до 60 секунд, максимум 2 попытки запуска lifecycle/engine вместе с откатом, 10 секунд стабильности, 300 секунд после неудачи и 120 секунд удержания успешного выбора. Прежние пользовательские интервалы сохраняются; сетевой timeout ограничивается остатком общего бюджета. Автовозврата на старый сервер нет. AWG и runtime имеют отдельные счётчики, не сбрасываемые при простом старте daemon/остановленном sing-box.

Daemon, CLI и LuCI используют общий operation lock. У процесса команды своя группа и проверяемая идентичность PID; падение владельца позволяет убрать его группу/маршруты по приватному манифесту. Незавершённый lock без доказуемого владельца отклоняется, а не удаляется наугад. Остановка службы также отменяет выполняющееся явное восстановление UI/CLI через поколение отмены. Пауза — немедленный сохраняемый сигнал отмены, поэтому может записываться без ожидания operation lock; выполняющаяся операция замечает изменение UCI и прекращает изменения. Подготовленные чужие UCI deltas не коммитятся. Контроль изменений оптимистический: перед/после команд сравнивается SHA256 экспортов backend, network, vpn_failover и pending deltas. Он не является общей транзакционной блокировкой для любых сторонних UCI-писателей.

Снимки выбранной конфигурации/runtime и состояний служб приватны, не попадают в журнал и удаляются при очистке. Откат не копирует старый конфиг поверх новых пользовательских настроек. Списки, DNS и подписки не отключаются ради прохождения проверки. Другие службы, маршруты управления, Tailscale и профили AWG не меняются. Перезапуск всей сети и глобальный flush отсутствуют.

## Протокол будущего физического пилота

Этот раздел — инструкция для отдельного согласованного этапа; **сейчас не выполнялся**.

1. Выбрать один пилот с независимым доступом и backup. Проверить точную версию backend/sing-box, UCI-схему, путь конфигурации, наличие рабочего section-specific API/inbound и поддержку `ip rule oif/protocol`. Зафиксировать hashes остальных секций, DNS, network, firewall, DHCP, Tailscale и состояния автозапуска.
2. Сохранить установленный пакет и UCI приватно, подготовить адресный возврат его файлов/настроек. Записать основной и разрешённые резервы по endpoint и проверить реальные egress. Задать только согласованный список выбранной секции.
3. Сначала режим паузы, proxy/direct и чтение страницы/status/dashboard: ноль запусков backend/engine и изменений выбора. Затем здоровый основной + runtime: ноль лишних reload/start.
4. По отдельности воспроизвести отказ основного с живым runtime; отказ основного с остановленным runtime; здоровый AWG с остановленным engine; остановку обоих backend/engine. Не трогать Tailscale. Инъекция отказа — только адресная, с заранее согласованным независимым автоматическим возвратом.
5. Проверить выбор NL/SE, генерацию новой привязки до engine, отсутствие дубля запуска, стабильные 10 секунд и HTTPS именно выбранной секции; подтвердить также доступ с LAN-клиента. Время после подтверждённого отказа до результата ≤180 секунд. Только здесь можно считать реальный обход восстановленным.
6. Проверить недоступность одного тестового ресурса, отсутствие handshake/WAN/резервов, отказ списков при здоровом AWG, ручной выбор во время операции, гонку UI/daemon, принудительное завершение worker и очистку ресурсов. Убедиться в отсутствии шторма и переключений туда-обратно.
7. Проверить field-only rollback, сохранность XBOX/CRYPTO и всех защищённых hashes/boot states. Обновить остановленную службу и убедиться, что она не запустилась. Скачать диагностический JSON и проверить отсутствие секретов.
8. Повторить главный сценарий на каждой из трёх поддержанных схем. Любая неподтверждённая версия/маршрут остаётся ограничением, а не успешной приёмкой. Массовое развёртывание согласуется отдельно после пилота.
