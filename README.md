# VPN Failover: Podkop, Forkop, Forkozz/NetShift

[English](README.en.md)

Разработка **0.3.0-dev**: код опубликован в репозитории, отдельный выпуск и проверка на роутере пока не выполнены. Проверенная ранее 0.2.1 содержит ошибку остановленного runtime и не считается исправленной. Исторические результаты старых версий приведены в [VALIDATION.md](VALIDATION.md).

Служба проверяет существующие AmneziaWG-туннели независимо от sing-box. При подтверждённом отказе основного выбирает разрешённый резерв, применяет только интерфейс выбранной секции, запускает родной backend и проверяет действующий маршрут. Если AWG работает, а движок остановлен, сначала восстанавливает тот же туннель. Подробности алгоритма и ограничения: [RECOVERY.md](RECOVERY.md).

## Обслуживание

Перед остановкой VPN-движка поставь Failover на паузу или останови его службу. Без явной паузы активная служба восстанавливает остановленный движок. Изменение поведения относительно 0.2.1 включено параметром `recovery_enabled=1`; `0` запрещает восстановление и переключения.

```sh
podkop-vpn-failover pause
podkop-vpn-failover resume
```

Пауза сохраняется в UCI и переживает перезапуск. `resume` снимает паузу, но сам не запускает остановленную службу Failover. `recover` выполняет один цикл с обычными порогами и выдержками; `reset` явно сбрасывает оба счётчика и выдержку. `status`, `dashboard`, `config`, открытие страницы и скачивание диагностики ничего не запускают, не проверяют сеть и не изменяют настройки.

## Настройки

Один экземпляр обслуживает одну именованную VPN-секцию. Настройки хранятся в `/etc/config/vpn_failover`. Пример предназначен для будущего согласованного применения; в ходе локальной разработки он не выполнялся:

```uci
config settings 'main'
    option backend 'forkozz'
    option section 'main'
    option paused '0'
    option recovery_enabled '1'
    list interfaces 'DE_custom'
    list interfaces 'NL_2'
    list interfaces 'SE_vpn'
    option check_interval '30'
    option fail_threshold '3'
    option candidate_success_threshold '2'
    option startup_grace_period '120'
    option no_reserve_retry_interval '300'
```

`backend`: `podkop`, `forkop`, `forkozz` или `auto`. Для восстановления полностью остановленного backend лучше явно задать его имя. Автоопределение опирается на действующую nft-таблицу/работающий процесс службы; остаточные конфиги не учитываются. Неоднозначность и другой одновременно работающий backend блокируют восстановление.

`interfaces` — **явный список разрешённых туннелей только этой секции**. Произвольные имена поддерживаются; протокол должен быть `amneziawg`. Пустой список допускает восстановление движка на текущем туннеле, но не выбор резервов. При обновлении список не заполняется всеми AWG автоматически: среди них могут быть отдельные XBOX/CRYPTO. Настройки других секций не меняются.

Опционально: `expected_egress_<имя интерфейса>` — ожидаемый внешний IP именно этого профиля, с учётом Exit node; `connect_timeout`, `max_time`, `quarantine_seconds`. Старые числовые настройки worker мигрируют в UCI, существующие значения UCI имеют приоритет. Значения сетевых таймаутов ограничены бюджетом операции.

## Интерфейс и журнал

«Службы → VPN Failover»: прежние кнопки управления, пауза/продолжение, восстановление и сброс счётчиков; отдельные признаки запущенной службы, автозапуска, runtime и подтверждённого обхода. Журнал сворачивается, содержит понятное описание и технические подробности. «Скачать логи» выгружает JSON без ключей, подписок и полных конфигураций.

История ограничена 200 событиями в RAM и очищается при перезагрузке. Успех `RECOVERED` появляется только после проверки процесса, конфигурации, привязки, правил и HTTPS через маршрут выбранной секции. Применённая настройка `SWITCH_APPLIED` ещё не является успехом.

## Установка и обновление

OpenWrt 24.10/opkg и 25.12/apk. Нужны `uci`, procd, `curl` с HTTPS, `jq`, `ip-full` с правилами `oif`/`protocol`, `nft`, `awg`, `ubus`, `setsid`, `logread`, BusyBox и `sha256sum`. Установщик устанавливает curl/jq, недостающие остальные зависимости диагностирует. Прошивку, Tailscale, SSH и AWG-профили не обновляет.

`install.sh` устанавливает worker и обязательную библиотеку `recovery.sh`, init/control, RPC и страницу. При обновлении делает приватный backup и сохраняет UCI, состояние Failover и его автозапуск. Ранее остановленный daemon не запускается; backend/sing-box самим установщиком не восстанавливаются. Новая установка остаётся остановленной, без автозапуска. В main находится версия разработки; перед установкой нужен отдельный согласованный пилот.

При отсутствии безопасного способа проверить маршрут движка возвращается `PATH_TEST_UNAVAILABLE`; служба не открывает тестовые порты и не выдаёт это за восстановление. См. [совместимость и будущий пилот](RECOVERY.md).

## Локальная проверка

```sh
sh -n podkop-vpn-failover
sh -n recovery.sh
python3 tests/test_backend.py
python3 tests/test_rpc.py
python3 tests/test_install.py
python3 tests/test_entrypoints.py
node tests/test_view.js
```

Тесты используют подменённые UCI, AWG, сеть и службы. Они не подключаются к клиентам и не заменяют физический пилот. Авторские права исходного проекта и [лицензия MIT](LICENSE) сохранены.
